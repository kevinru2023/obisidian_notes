## Core ML Framework (from L1.2)

Every supervised ML problem involves:
- **Dataset** $D = \{(x_i, y_i)\}$ — labeled training examples
- **Hypothesis space** $\mathcal{H}$ — the set of functions the model can represent
- **Loss function** $\mathcal{L}$ — quantifies prediction error
- **Learning algorithm** $A$ — finds the best $h \in \mathcal{H}$ minimizing $\mathcal{L}$

**Error decomposition:**
- **Bayes error** — irreducible; inherent randomness in the true function
- **Modelling error** — H isn't expressive enough (underfitting)
- **Estimation error** — finite data; best h in H given ∞ data ≠ best h given D
- **Optimization error** — algorithm doesn't perfectly minimize the loss

## Key Algorithms Covered

### k-Nearest Neighbors (L1.2)
Non-parametric; no training step (lazy learner). See [[wiki/concepts/knn]].

### MLE / MAP (L2.1)
Statistical framework for learning. MLE maximizes P(D|θ); MAP adds a prior P(θ). See [[wiki/concepts/mle-map]].

### Linear Regression (L2.2, L3.1)
- Minimize $\text{SSE} = \sum_i (y_i - w^\top x_i)^2$ — closed-form: $w^* = (X^\top X)^{-1} X^\top y$
- Extend with **basis functions** $\phi(x)$ to fit nonlinear data with a linear model
- **Ridge regularization**: add $\lambda\|w\|^2$ to loss → shrinks weights, reduces overfitting
- See [[notes/courses/ML/Linear Regression]]

### Logistic Regression & Perceptron (L3.2)
Binary classifiers. See [[wiki/concepts/logistic-regression]].

### Naïve Bayes (L4.1)
Generative classifier. Assumes features are conditionally independent given the class. Predicts via $\operatorname{argmax}_c P(y=c)\prod_i P(x_i \mid y=c)$. Variants: Bernoulli NB (binary features), Categorical NB, Gaussian NB (continuous features). See [[wiki/concepts/naive-bayes]].

### Support Vector Machines (L5.1)
Find the linear decision boundary maximizing the margin between classes. **Hard-margin SVM**: assumes linear separability; minimizes $\frac{1}{2}\mathbf{w}^\top\mathbf{w}$ subject to $y_i(\mathbf{w}^\top\mathbf{x}_i + b) \geq 1$. **Soft-margin SVM**: allows margin violations via slack variables $\xi_i$; adds $C\sum_i \xi_i$ penalty. $C$ controls the margin–error tradeoff. Solution is a sparse sum over support vectors. See [[wiki/concepts/svm]].

### Kernel Methods (L6.1)
Basis function maps $\Phi: \mathbb{R}^d \to \mathbb{R}^{d'}$ allow nonlinear decision boundaries, but computing high-dimensional feature vectors is expensive. The **kernel trick** replaces explicit feature computation with a kernel function $\kappa(\mathbf{a},\mathbf{b}) = \Phi(\mathbf{a}) \cdot \Phi(\mathbf{b})$, computing dot products in the mapped space in $O(d)$ instead of $O(d^{p})$. Valid kernels are characterized by Mercer's theorem (PSD Gram matrix). Kernels can be applied to SVMs, the perceptron, and ridge regression by expressing each algorithm's dual via pairwise dot products and substituting $\kappa$. Common kernels: linear, polynomial, RBF (infinite-dimensional). See [[wiki/concepts/kernel-methods]].

## Model Selection & Evaluation

**The golden rule**: never use the test set for tuning. Workflow:
1. Split data into train / validation / test
2. Tune hyperparameters using validation performance
3. Report final numbers on test set (once, at the end)

**K-fold cross-validation**: split training data into K folds; rotate which fold is validation. Average performance across folds. More reliable when data is scarce.

**Leave-one-out (LOO)**: K = n. Expensive but unbiased. For kNN, LOO is cheap — just exclude each point from its own neighborhood.

**Evaluation metrics for classifiers:**
- **Accuracy** $= (TP + TN) / \text{total}$ — misleading when classes are imbalanced
- **Precision** $= TP / (TP + FP)$ — "of those I said positive, how many were?"
- **Recall** $= TP / (TP + FN)$ — "of the true positives, how many did I catch?"
- **F1** $= 2 \cdot P \cdot R / (P + R)$ — harmonic mean

## Practical Issues (CIML Ch. 5)

- **Feature scaling**: normalize features to [0,1] or z-score; kNN and gradient descent both sensitive to scale.
- **Feature engineering**: domain knowledge → better representations → huge performance gains (often bigger than algorithm choice).
- **Irrelevant features**: hurt kNN by polluting distance. Consider feature selection or dimensionality reduction.
- **Debugging**: if model underperforms, first check data quality and feature representation before switching algorithms.
