## Lecture Topics

### Lecture 01: Introduction
→ See [[wiki/concepts/parallel-programming-fundamentals]] for full coverage.

Key themes: why parallelism (clock speed plateau), data vs. task parallelism, Flynn's taxonomy (SISD/SIMD/MIMD), shared vs. distributed memory architectures, supercomputer design (Summit node layout).

### Lecture 02: Cache-Based Optimizations
→ See [[wiki/concepts/cache-optimization]] for full coverage.

Key themes:
- Memory hierarchy and locality (temporal/spatial)
- Cache performance metrics: miss rate, hit time, miss penalty
- Register reuse in matrix multiplication
- Loop ordering effects on cache miss rates (ijk vs ikj vs kij vs jki/kji)
- Blocked (tiled) matrix multiplication: reduces total misses from $O(n^3)$ to $O(n^3/B)$
- Roofline model (reference: Williams, Waterman, Patterson, CACM 2009)

### Lecture 03: Cache Continued + OpenMP Basics
→ See [[wiki/concepts/cache-optimization]] (updated with performance calculations) and [[wiki/concepts/openmp]].

Key themes: full loop-order miss analysis with numeric examples and quiz-style timing calculations; OpenMP overview — fork-join model, shared vs. private variables, pragma syntax, comparison with Pthreads/TBB/CILK.

### Lecture 04: OpenMP Continued
→ See [[wiki/concepts/openmp]] for full coverage.

Key themes: race conditions and deadlocks, OpenMP common core table, thread functions (`omp_get_thread_num`, `omp_get_num_threads`, `omp_get_wtime`), π computation SPMD pattern, false sharing diagnosis and fixes (padding, private scalar + critical), synchronization (`critical`, `barrier`), parallel loops (`#pragma omp for`, `#pragma omp parallel for`), schedule clauses (static/dynamic/guided), loop-carried dependency removal, reduction clause.

### Lecture 05: OpenMP Continued
→ See [[wiki/concepts/openmp]] for full coverage.

Key themes: MESI cache coherence (Modified/Exclusive/Shared/Invalid states and transitions), parallel loop schedule clauses (`static`/`dynamic`/`guided`), `nowait` to skip implied barriers, data environment clauses (`private`/`firstprivate`/`default(none)`), Mandelbrot set exercise (race condition on `numoutside`, misuse of `private` on global struct), matrix-matrix multiplication in OpenMP, OpenMP tasks — `single`, `task`, `taskwait`, linked list traversal, recursive Fibonacci with tasks.

### Lecture 06: OpenMP Tasks + Performance Analysis
→ See [[wiki/concepts/openmp]] for task content; [[wiki/concepts/parallel-performance]] for performance content.

Key themes: Reduction vs. critical comparison (private-copy model vs. mutex), task data scope defaults (firstprivate by default for private outer variables), divide-and-conquer $\pi$ computation with tasks and `MIN_BLK` threshold; Roofline model (memory-bound vs. compute-bound, operational intensity); general speedup formula ($\sigma$, $\varphi$, $\kappa$ decomposition), parallel efficiency $\varepsilon = \psi/p$; Amdahl's Law ($\psi \leq 1/(f + (1-f)/p)$, fixed problem size), Gustafson-Barsis Law ($\psi \leq p + (1-p)s$, scaled speedup, fixed wall-clock time).

### Lecture 07: GPU and CUDA Basics (1)
→ See [[wiki/concepts/gpu-cuda]] for full coverage.

Key themes: CPU clock plateau and the case for GPUs; heterogeneous computing (latency-optimized CPU vs. throughput-optimized GPU); SIMD evolution (MMX→SSE→AVX→AVX-512) and why neglecting SIMD is increasingly costly; GPGPU history; GPU programming models (CUDA, OpenACC, ROCm/HIP, OpenCL, SYCL) and why CUDA dominates; CUDA minimal extensions (`__global__`, `__device__`, `__shared__`, `<<<grid, block>>>`); step-by-step CUDA programming (host alloc → device alloc → H2D copy → kernel launch → D2H copy); GPU thread hierarchy — Thread→Core, Block→SM, Grid→GPU; `dim3` for multi-dimensional grids and blocks; hardware limits (max 1024 threads/block, max $2^{31}-1$ blocks in x); stride-loop pattern for arrays larger than the grid.

### Lecture 08: GPU and CUDA Basics (2)
→ See [[wiki/concepts/gpu-cuda]] for full coverage.

Key themes: Warp divergence — within-warp divergence causes serialization (bad), between-warp divergence does not; warp scheduler hides memory latency by switching to ready warps; GPU memory hierarchy — registers (fastest, ~10× faster than shared), shared memory (on-chip per block, same hardware as L1), local memory (off-chip reserve of global memory), global memory (DRAM, slowest); memory coalescing — 32-byte L2 transactions, aligned sequential access = 100% bus utilization, strided or random access wastes bandwidth; AoS vs. SoA layout; shared memory bank conflicts (32 banks, bank $= i \bmod 32$, conflicts serialize access); register spilling to local memory; parallel reduction — kernel decomposition instead of global sync, interleaved addressing (divergent warps), sequential addressing (bank-conflict-free), warpReduce unrolling for the last warp (requires `volatile`).
